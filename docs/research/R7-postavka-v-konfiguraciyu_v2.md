# Диадок в основной конфигурации: схема ветки Т-33

## 0. Как читать

**Ссылки.** `S###:L…` — источник и строки по [01_istochniki.md](01_istochniki.md). Гайды S001–S003 лежат рядом с этим файлом. Остальные источники — в `materials2.zip`: собрать `zip -s 0 materials2.zip --out full.zip` и распаковать **вне git**.

**Пометки достоверности:**

| Пометка | Значение |
|---|---|
| **[код]** | проверено по коду репозитория (`SRC/`, R1–R6) |
| **[оф.]** | официальный источник из материалов, текст прочитан |
| **[неоф.]** | Инфостарт, форумы, сводки-гайды |
| **[вывод]** | наше умозаключение, прямой цитаты нет |
| **[не проверено]** | гипотеза; проверяется на тестовой базе (§6) |

**Короткий ответ.** Схема реализуема силами платформы, без вендора. Контур не выпускает cf-поставку модуля, поэтому её собираем сами — конвертацией каждого релиза `.cfe`. Конвертация простая: модуль ничего не заимствует из УТ, кроме языка. Две меры делают второго поставщика почти бесконфликтным: **пустой корень** и **закреплённые UUID**. Цена схемы — недоступна Контур.Интеграция (ей нужен модуль-расширение) и неофициальный статус сборки.

Где выполняется: тестовая ИБ (копия прода, Т-14) и буферная пустая база; Windows, PowerShell, Конфигуратор в пакетном режиме (Т-13, Р-4).

| № | Шаг | Вход → выход | Зачем | Метка |
|---|---|---|---|---|

**Конфликты, которые выдаёт конвейер:**
1. Объект, который «обновление невозможно» на шаге 4. Значит, кто-то правил объект поставщика руками — нарушение схемы.
2. Метод вендора, перехваченный `&ИзменениеИКонтроль`, у которого изменился текст. Из-за возможного молчаливого отката (§1.3) сверка обязательна на каждом релизе.
3. Форма вендора, у которой изменились элементы, к которым привязано наше программное добавление.
4. Ошибки `/CheckModules` и проверки применимости.

Позиции 7 и 8+13 эскалируются архитектору (Т-19).

## 3. Решения внутри схемы

### 3.1. Формы вендора — программно (Т-11, Т-12)

Наше расширение заимствует форму из поставки «Диадок» (она теперь объект основной конфигурации). Дальше `&После("ПриСозданииНаСервере")`: `ИзменитьРеквизиты` → `Команды.Добавить` → `Элементы.Добавить/Вставить`. Визуально заимствованную форму не правим, `Form.xml` остаётся как у вендора. [оф. + неоф., §1.3]

Почему для этого вообще нужна поставка в конфигурации: объект одного расширения из другого расширения заимствовать нельзя [неоф., форумы; официального текста запрета в материалах нет — 04_probely.md Q11].

### 3.2. Пустой корень поставки [вывод, не проверено]

Корень — всегда сопоставленный объект двух поставок (S001:L81). Если оставить в `Диадок.cf` модуль сеанса и командный интерфейс вендора, на каждом обновлении УТ и Диадока будет конфликт в корне.

**Решение:** скрипт конвертации выбрасывает из поставки `Ext/SessionModule.bsl` и `MainSectionCommandInterface`. Вызов вендора переезжает в наше расширение:

```bsl
// Наше расширение, модуль сеанса (заимствован из основной конфигурации)
&После("УстановкаПараметровСеанса")
Процедура НашеУстановкаПараметровСеанса(ИменаПараметровСеанса)
	КонтурДиадокСервер.УстановкаПараметровСеанса(ИменаПараметровСеанса);
КонецПроцедуры
```

Что делает фрагмент: после типовой установки параметров сеанса вызывает инициализацию Диадока — ровно то, что сейчас делает расширение вендора (`SRC/TypeDiadok/Ext/SessionModule.bsl`).

Командный интерфейс раздела настраивается в нашем расширении так же.

**Итог:** поставка «Диадок» содержит только собственные объекты; пересечение с 1С — только формальное, через корень, без изменённых свойств.

Проверить (§6, п. 3): что `/MergeCfg` с «пустым» корнем не меняет свойства корня УТ.

### 3.3. Закрепление UUID [вывод, не проверено]

UUID объектов вендора различаются даже у разных сборок одной версии (§1.1). Если они «плавают» между релизами, `/UpdateCfg` увидит «удалили и добавили заново». Для обработок и модулей это безвредно (данных нет). Для **роли** вредно: назначение роли пользователям хранится по идентификатору (S001:L68 — общий принцип).

**Решение:** при первой установке скрипт сохраняет карту «полное имя объекта → UUID» (в git). При каждой конвертации UUID в XML проставляются по карте; у новых объектов остаются как у вендора и дописываются в карту.

После этого стабильность UUID у вендора не важна, а открытый вопрос «нужен предыдущий релиз `.cfe`» (04_probely.md) снимается.

Риск: UUID встречаются в перекрёстных ссылках (типы, формы). Заменять нужно во всех файлах сразу, и проверяется это первым же опытом на базе (§6, п. 2).

### 3.4. Позиции 7, 8, 13 — без глобальной переменной

Новые параметры передаются полями структур, которые вендор уже передаёт:
- договор — в **копии** `ДанныеКонтрагента.Договор1С`;
- единица — полем строки номенклатуры.

Тогда новые функции вендора сами несут договор, а перехват уходит с `&ИзменениеИКонтроль` на каждый метод к `&Перед`/`&После` в точках, где структура формируется.

**Условие [не проверено]:** по пути никто не берёт `ДанныеКонтрагента` заново из кэша — проверить по коду до решения (R5).

### 3.5. Автообновление и позиция 11

Модуль, запущенный из обработок конфигурации, автообновление не получает [оф., S042:L63-L67]. Значит, в этой схеме защита от автообновления не нужна, а позиция 11 («КС всегда валидна») теряет смысл [вывод]. Флаг на тарифе «Стартовый» тоже не мешает.

До перехода риск остаётся: Т-20 — проверить флаг в проде сейчас.

### 3.6. Подсистема хранения

`diadoc_storage_cfg.cf` уже стоит в основной конфигурации. Состояние её поддержки в проде неизвестно — вопрос пользователю (§7).

Варианты:
- **(а)** модуль — отдельным поставщиком. Просто, поставщиков становится три.
- **(б)** общий cf «хранилище + модуль» одним поставщиком. Чище, но поставку хранилища тоже собираем мы.

## 4. Запасной путь «только Конфигуратор» (Т-32)

Исправление к v1: там было сказано, что конвертацию Конфигуратор не заменяет. Неверно — «Выгрузить/Загрузить конфигурацию в файлы» есть в меню Конфигуратора (S003:L29, S003:L54), руками остаётся только правка текста XML.

1. Буферная база → «Конфигурация → Расширения» → загрузить `.cfe` → «Выгрузить в файлы».
2. В блокноте:
   - удалить 4 строки в `Configuration.xml`;
   - удалить `Adopted` во всех XML;
   - удалить `Ext/SessionModule.bsl` и командный интерфейс;
   - UUID по карте — поиском и заменой.

   Карта UUID короткая: роль, подсистема, параметр сеанса, общая команда, картинка — критична только роль.
3. Пустая база → «Загрузить конфигурацию из файлов» → «Сохранить конфигурацию в файл» → `Диадок.cf`.
4. Рабочая копия → «Поддержка → Обновить конфигурацию» → `Диадок.cf`, настройки объединения из файла.
5. «Обновить конфигурацию БД» → загрузить наше расширение → «Проверить применимость».

Если шаг 2 не получается — в git лежит `Диадок.cf` прошлого релиза, откат без потерь.

## 5. Плюсы и цена схемы

| Критерий | `.cfe` как есть + наше расширение / ПМ | Диадок в конфигурации + наше расширение (Т-33) |
|---|---|---|
| Формы и методы вендора из нашего расширения | нельзя (расширение не заимствует из расширения, неоф.) | штатно |
| Автообновление | работает, нужно выключать (Т-20) | недоступно официально (S042) |
| Контур.Интеграция (4.69+) | доступна | **недоступна** (S002:L145) |
| Конфликты с релизами УТ | нет | только корень; при «пустом корне» — формально |
| Работа на релиз | слияние нашей дельты в коде вендора | конвертация (скрипт) + `/UpdateCfg` + проверки |
| Статус у Контура | доработанный модуль → «Оставить заявку» | то же, плюс неофициальная сборка |
