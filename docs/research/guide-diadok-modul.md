## 1. Варианты поставки и их выбор

| Критерий | Расширение конфигурации (.cfe) | Внешняя обработка (.epf) |
|---|---|---|
| Рекомендация | основной вариант | альтернативный |
| Автообновление | да, без участия специалистов | да |
| Интеграция в интерфейс | полная (команды в документах/списках) | нет — отдельная форма |
| Производительность | высокая (нативная работа с метаданными) | средняя (метаданные загружаются динамически при каждом запуске) |
| Платформа | 8.3.14+ | 8.2.19+ |
| Конфигурация | только ПРОФ/КОРП | любая, включая Базовую |
| Режим запуска | тонкий клиент (управляемое приложение) | тонкий клиент; толстый клиент (обычное приложение) — с ручной настройкой интерфейса |

- Для Базовых версий и платформы ниже 8.3.14 расширение **не подходит** — остаётся `.epf`.
- В толстом клиенте команды расширения не встраиваются в интерфейс автоматически — кнопку запуска модуля размещают вручную.
- **Переход с обработки на расширение** бесшовный: документы Диадока, настройки подключения и история обмена остаются в базе, ручной перенос/конвертация не нужны. Проверка версии платформы: «Ещё → О программе»; при 8.3.14+ — скачать дистрибутив расширения или использовать установщик.
- Новые функции выходят в первую очередь (иногда exclusively) для формата расширений.
- Режим совместимости основной конфигурации для расширения модуля (`diadoc_um.cfe`) — не ниже **8.3.14**; для расширения подсистемы хранения (`diadoc_storage_ext.cfe`) — не ниже **8.3.20**, версия универсального модуля — не ниже **4.44**.

## 2. Центр загрузок: что качать

**Основная поставка:**
| Файл | Тип | Назначение |
|---|---|---|
| `diadoc_installer.epf` | мастер установки | сам определяет вариант поставки и ставит |
| `diadoc_um.cfe` | расширение конфигурации | основная функциональность, режим совместимости от 8.3.14 |
| `diadoc_um.epf` | внешняя обработка | основная функциональность, любые конфигурации |

**Дополнительные компоненты:**
| Файл | Тип | Назначение |
|---|---|---|
| `kontur_integration_inst.epf` | установщик расширения | подключение Контур.Интеграция (кнопки в карточках документов) |
| `diadoc_storage_cfe.cfe` | расширение конфигурации | подсистема хранения; не меняет основную конфигурацию; совместимость от 8.3.20 |
| `diadoc_storage_cfg.cf` | файл конфигурации | подсистема хранения с модификацией основной конфигурации; для любых конфигураций |
| `diadoc_ScheduledJobs.epf` | внешняя обработка | запуск регламентных заданий (обязательно при поставке модуля расширением) |

Всё на странице https://support.kontur.ru/diadoc-1s8x/85004-centr_zagruzok.

## 3. Обновление модуля

С версии **4.15** есть автообновление (включено по умолчанию; управление — «Настройки → Расширенные настройки → Системные»). Автообновление недоступно, если модуль запускается на устаревшей/неподдерживаемой конфигурации или из обработок конфигурации. Ручное обновление — тремя способами:

### 3.1. Как обычный файл (файл `Diadoc1C_хх_хх.epf`)
1. Меню (значок в правом верхнем углу) → «Файл» → «Открыть».
2. Выбрать скачанный файл.
3. На предупреждения отвечать «Да».

### 3.2. Как внешнюю обработку (через справочник «Дополнительные отчеты и обработки»)
Пути по конфигурациям:
- БП 3.0/КОРП 3.0: «Администрирование → Печатные формы, отчеты и обработки → Дополнительные отчеты и обработки»;
- ERP УП 2: «НСИ и администрирование → Администрирование → Печатные формы…»;
- БП 2.0/КОРП 2.0: «Сервис → Дополнительные отчеты и обработки → Дополнительные внешние обработки»;
- УТ 10.3, КА 1.1: «Сервис → Внешние печатные формы и обработки → Внешние обработки»;
- УПП 1.3: «Сервис → Дополнительные внешние отчеты и обработки → Обработки»;
- АА 5.1: «Сервис → Внешние обработки и отчеты → Обработки».

Дальше:
- управляемые формы (БП 3.0, УТ 11.4/11.5, ERP УП 2.4/2.5, КА 2.4/2.5, УФ 1.6): «Обновить из файла…» → выбрать файл → при необходимости задать размещение (кнопка «Не задано») → «Записать и закрыть»;
- обычные формы (БП 2.0, УПП 1.3, УТ 10.3, КА 1.1, АА 5.1): «Добавить» → наименование → файл → «ОК»; запуск из места размещения кнопкой «Выполнить»;
- если список обработок пуст — ссылка «Настроить список», отметить обработку Диадока;
- окно «Хранение данных» = нестандартная конфигурация 1С → см. «Обновление базы 1С» Контура.

### 3.3. Как расширение (файл `diadoc_х_xх_х.cfe`)
1. Открыть список расширений: БП 3.0 — «Администрирование → Печатные формы, отчеты и обработки → Расширение»; УТ 11.4/11.5, ERP УП 2.4/2.5, КА 2.4/2.5 — «НСИ и администрирование → … → Расширение».
2. Отметить расширение «Контур.Диадок» → «Обновить из файла» → выбрать `.cfe`.
3. Дождаться завершения, **перезапустить 1С**.

Кнопка «Оставить заявку на подключение» в модуле = в модуле есть доработки; обновляться через администратора/поддержку. Обновление не влияет на работу 1С, данные сохраняются.

Скачать обновление можно и из самого модуля: меню → «Скачать обновление модуля» → выбрать папку → «Скачать обновление модуля».

## 4. Подсистема хранения: два способа внедрения

### 4.1. Расширение (diadoc_storage_ext.cfe) — без изменения основной конфигурации
Требования: режим совместимости основной конфигурации **не ниже 8.3.20**, модуль не ниже **4.44**, монопольный доступ.
1. «Конфигурация → Открыть конфигурацию».
2. «Конфигурация → Расширения конфигурации» → «Добавить» → в окне нового расширения ничего не менять → «ОК».
3. ПКМ по добавленному расширению → «Конфигурация → Загрузить конфигурацию из файла…» → выбрать `diadoc_storage_ext.cfe` → подтвердить изменение текущей конфигурации расширения.
4. «Обновить конфигурацию базы данных» (нужна монопольность).
5. Снять флажок **«Безопасный режим»** и установить **«Использовать основные роли для всех пользователей»**.

### 4.2. Подсистема конфигурации (diadoc_storage_cfg.cf) — с изменением конфигурации
См. §4 (добавление) и §5 (обновление) ниже. Подходит для любых конфигураций.

## 5. Добавление объектов Диадок в конфигурацию (cf-путь)

Перед началом: **резервная копия базы**. Контур не гарантирует корректную работу модуля, добавленного в расширение (тогда — через поддержку/администратора).

Порядок (все шаги):
1. **Файл**: скачать `diadoc_storage_cfg.cf` (подсистема конфигурации).
2. **Открытие конфигурации**: база в режиме «Конфигуратор» → «Конфигурация → Открыть конфигурацию».
3. **Правила поддержки** (если конфигурация на замке):
   - «Конфигурация → Поддержка → Настройка поддержки…» → «Включить возможность изменения» → «Да» на предупреждение о невозможности автоматического обновления;
   - выбрать «Объект поставщика не редактируется» → «ОК»;
   - в списке объектов ПКМ на строке «Не редактируется» → «Установить правило поддержки» (существующие объекты менять по-прежнему нельзя — поддержка сохраняется; правило для корневого узла разрешает **добавление новых** объектов);
   - в «Настройке правил поддержки» выбрать «Объект поставщика редактируется с сохранением поддержки», снять флажок «Установить для подчиненных объектов» → «ОК».
4. **Объединение**: «Конфигурация → Сравнить, объединить с конфигурацией из файла…» → `diadoc_storage_cfg.cf` → «Да» → **снять флажок в корне дерева** → «Действия → Отметить по подсистемам файла» → подсистема **«КонтурДиадокХранилище»** → проверить: снят флажок «Не входящие в подсистемы», установлен «Включать объекты подчиненных подсистем», снят «Включать объекты родительских подсистем» → «Установить» → в окне сравнения «Выполнить» → «ОК» → «Сохранить» → «ОК».
5. **Сохранение**: «Конфигурация → Обновить конфигурацию базы данных» → «Принять».
6. **Права**: «Администрирование → Пользователи» → вкладка «Прочие» → роль **«Диадок: Полные права (хранилище)»**.

## 6. Обновление объектов (уже добавленных) — отличия от добавления

1. Скачать свежий `diadoc_storage_cfg.cf`.
2. Конфигуратор → «Конфигурация → Открыть конфигурацию».
3. **«Конфигурация → Поддержка → Обновить конфигурацию»** (не сравнение!) → «Выбор файла обновления» → указать файл → «Далее» → «Готово» → «ОК».
4. Снять флажок в корне дерева → «Действия → Отметить по подсистемам файла» → «КонтурДиадокХранилище» → те же три флажка (как в §5.4) → «Установить» → «Сохранить» → «ОК» → «ОК».
5. «Конфигурация → Обновить конфигурацию базы данных» → «Принять».
6. Запустить модуль; при запросе на обновление данных — «Обновить и перезапустить», затем перезапустить модуль.

## 7. Системные настройки модуля (что важно при сопровождении)

Путь: «Настройки → Расширенные настройки → Системные».
- **Обновление**: «Автоматически обновлять модуль» (по умолчанию вкл; на тарифе «Стартовый» не отключается); недоступно на устаревших/неподдерживаемых конфигурациях и при запуске из обработок конфигурации. «Учетная запись для обмена с сервером» — служебный логин/пароль с доступом ко всем подразделениям, кнопка «Проверить авторизацию».
- Обработка документов: плагины; контроль дублирования пакетов на отправку (вкл. по умолчанию); анализ входящих (не для «Стартового»); Контур.Маркировка.
- Оптимизация (только при добавленных объектах Диадока): уведомления о событиях контрагентов; хранение файлов на диске; удаление содержимого устаревших документов (в днях, только для системы хранения «объекты Диадока»); фоновые операции (ускоряют обмен на серверных базах; с 4.64 — и в файловых базах с платформой выше 8.3.3 в управляемом режиме).
- Тестирование и отладка: режим отладки; режим логирования (`*.txt`); «Выполнить регламентные действия» (только при индивидуальной настройке ПМ).

## 8. Подключаемый модуль (ПМ) — краткая выжимка техдока

- ПМ — вспомогательная внешняя обработка с функциями обработки событий под конкретную конфигурацию/бизнес-процессы; расширяет универсальный модуль там, где типового функционала не хватает (нестандартные бизнес-процессы, доработанные конфигурации).
- События ПМ: сбор данных из 1С для отправки на сервер Диадока; обработка полученных с сервера данных и регистрация в базе (например, создание документа поступления из входящего УПД).
- Точка входа — функция `ОбработатьСобытие`; диспетчеризация через «Если ИмяСобытия = "…" Тогда Возврат ИмяФункции(Параметры)».
- Умеет: сбор пакетов, заполнение контента, сопоставление/создание документов, анализ входящих, доработка таблицы списка (колонки), кнопки, регламентное задание, сопоставление номенклатуры.
- Настройка в модуле: «Настройки → Расширенные настройки → Подключаемый модуль»; источник — «В справочнике 1С» (внешняя обработка из доп. отчётов) или «Выбрать файл»; после сохранения перезагрузить 1С. Недоступно на тарифе «Стартовый».
- Новые ПМ создаются Генератором ПМ. В техдоке: политика устаревания публичных методов, отладка, плагины, методология обновления, обновление УКД 736→29, УПД 820→970, переход на НДС 22%, Универсальные сообщения.

## 9. Расширение Контур.Интеграция

- Что даёт: отправка из карточки документа 1С («Отправить ЭД»), просмотр статуса («Открыть ЭД»), переход в модуль («Перейти в Диадок»).
- Требования: модуль Диадок от **4.69.0**, установленный как расширение; права пользователей на модуль. Совместимые конфигурации: БП 3.0/КОРП 3.0 (3.0.180+), ERP УП 2.4 (2.4.14+)/2.5 (2.5.22+)/2.6 (2.6.1+), КА 2.4/2.5/2.6, УТ 11.4 (11.4.14+)/11.5 (11.5.22+)/11.6 (11.6.1+).
- Установка/обновление: скачать `kontur_integration_inst_x_x_xx.epf` → 1С под полными правами → «Файл → Открыть» → мастер → «Установить»/«Обновить» → перезапуск 1С.

## 10. Заметки для планирования обновлений (из «Новое в модуле» и новостей)

- Актуальная линейка: 4.70.0 (30.09.2026), 4.68.0, 4.67.0, 4.66.0… — смотреть «Новое в модуле».
- Авторизация: с 4.66 вход через единый портал Контура по **OpenID Connect** (старые способы аутентификации исключены); автоматическое продление сессии (обновление токена) — при входе через Портал.
- С **1 сентября 2026** прекращается развитие и поддержка **COM SDK**.
- Модули ниже **4.47.23** не работают с обновлённым форматом УПД (970) — обязательный минимальный уровень при обновлении.
- Новые форматы ФНС: приказ от 19.01.2026 № ЕД-1-26/29@ (ЭДО, корректировочные документы) — поддержан в УТ 11, ERP УП 2, КА 2 начиная с 4.70; счёт на оплату по приказу № ЕД-7-26/29@ — поэтапно с 4.62–4.65.
- Фоновые операции в файловых базах (управляемое приложение, платформа >8.3.3) — с 4.64 при запуске из расширения или из файла при наличии подсистемы хранения.
- Прекращена продажа модуля для 1С 7.7 новым клиентам (ноябрь 2024).
