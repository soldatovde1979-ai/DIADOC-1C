## 1. Зачем [План: шаг 8, «Зачем»]

Проверить цель — обновление за 1–1,5 часа (my-FT Т-1) — на настоящих релизах, а не на оценке. Убедиться, что обновление делает стажёр (Т-18) и ошибки ловит машина (Т-4).

## 2. Вход [План: шаг 8, «Вход»]

- Прод на 4.61.1 по новой схеме (ТЗ-7).
- Два релиза Контура: **первый — актуальный (4.70 или новее)**, второй — следующий квартальный.

## 3. Что сделать [План: шаг 8, «Что делаем»]

### 3.1. Обновление 1 — 4.61.1 → актуальный релиз

- Делает стажёр по регламенту, архитектор рядом.
- Скачок через несколько версий — **самый тяжёлый** прогон: ожидаем конфликты в проверке 3 и отличия эталонов из-за новых форматов (например, УПД 970 по приказу ЕД-1-26/29@ — S002:L154). Этот прогон и есть настоящая проверка схемы.
- Отличия эталонов, вызванные новым поведением вендора, архитектор подтверждает, эталон обновляется (ТЗ-7 §4.3).

### 3.2. Обновление 2 — следующий квартальный релиз

- Стажёр сам, по регламенту; архитектор — только на эскалации (Т-19) и подтверждении прода.
- Это прогон «как будет всегда»: по нему меряем цель.

### 3.3. Замеры

Источник — журнал `update.ps1` (время этапов) плюс отметки стажёра для ручных шагов (smoke, разбор, прод).

| Метрика | Цель | Где берём |
|---|---|---|
| Время обновления 2 от скачивания до smoke на проде, без шага 0 регламента | ≤ 1,5 ч (Т-1) | журнал + отметки |
| Время архитектора на обновлении 2 | ≤ 1 ч | отметки |
| Ошибки по нашим доработкам, найденные пользователями после обновления | 0 (Т-4) | обращения за 2 недели после обновления |
| Конфликтов в отчёте, разобранных стажёром без архитектора | все, кроме поз. 7, 8, 13 | отчёт |
| Время старого ручного обновления по шагам (для экономики) | — | архитектор оценивает задним числом последнее ручное обновление (my-FT Р-6) |

### 3.4. Отчёт (ИИ)

`docs/priemka.md`: замеры, что пошло не так, какие правки внесены в регламент и скрипты, пересчёт окупаемости (план §6.4) по фактическому времени.

## 4. Выход [План: шаг 8, «Выход»]

| Артефакт | Где |
|---|---|
| Два обновления на проде | прод |
| Отчёт приёмки | `docs/priemka.md` |
| Уточнённые регламент и скрипты | `docs/reglament.md`, `tools/` |

## 5. Критерии приёмки

1. Обновление 2 уложилось в 1,5 ч и выполнено стажёром.
2. После обоих обновлений нет ошибок по доработкам у пользователей в течение 2 недель.
3. Архитектор подписывает отчёт: «принято» или «доработать — что именно».

После «принято»:
- `SRC/ERPDiadok` переносится в архив (выгрузка старой схемы больше не нужна);
- `spec.md` — в архив (my-FT Р-9);
- `agent.md` переписывается под итоговую схему.

## 6. Чего этот шаг не делает

- Не меняет схему; найденные улучшения — отдельными задачами.
