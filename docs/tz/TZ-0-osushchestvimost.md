## Глоссарий (термины этого ТЗ)

| Термин | Что это простыми словами |
|---|---|
| **Расширение конфигурации (AddOn)** | «Надстройка» над конфигурацией 1С в отдельном файле `.cfe`. Модуль Диадок вендор поставляет именно так — как расширение `КонтурДиадок`. При обновлении вендор присылает новое расширение целиком. |
| **Основная конфигурация** | Сама УТ11 со всеми нашими объектами `т1к*`. Обновление модуля Диадок её не трогает. |
| **Заимствование** | Приём, когда расширение «подменяет» объект основной конфигурации своей копией. Работает только для объектов основной конфигурации — объекты **другого расширения** заимствовать нельзя. |
| **ПМ, подключаемый модуль** | Наша обработка `ДД_подключаемыйМодуль`. Вендор сам вызывает её в определённых местах («событиях»): «подготовь пакет», «подготовь документ» и т. д. Это официальный способ встроить свою логику. |
| **Местонахождение ПМ** | Настройка модуля Диадок: откуда брать ПМ — «Конфигурация» (обработка в базе), «Диск» (файл) или «1С» (справочник доп. обработок). |
| **Допущение (гипотеза)** | То, на что опирается план, но что ещё не проверено на живой 1С. Если допущение не подтвердится — план правится до начала работ. |
| **Тестовая база** | Копия рабочей базы для экспериментов. На ней можно ломать — прод не пострадает. |
| **Служебная база** | Пустая файловая база УТ11 для выгрузки чистого дистрибутива вендора в файлы. |
| **Пакетный режим Конфигуратора** | Запуск `1cv8.exe DESIGNER …` с ключами из командной строки, без окон: выгрузить, загрузить, проверить модули. Нужен для автоматизации. |
| **Выгрузка в файлы** | Сохранение конфигурации/расширения в набор текстовых файлов (`.xml`, `.bsl`). Именно с такими файлами работают git и ИИ. |

## 1. Зачем это и что делаем (суть простыми словами)

План v3 стоит на нескольких допущениях о том, как ведёт себя 1С и модуль вендора. Часть из них уже **проверена чтением кода** (§2), но код — это ещё не работающая система. Если хоть одно ключевое допущение окажется неверным, а мы уже потратим недели на Шаги 1–4, — работа пойдёт в корзину.

Поэтому первый шаг — дёшево (1–2 дня) проверить на тестовой базе всё, на чём держится план:

- можно ли держать наш ПМ в основной конфигурации, а не внутри расширения вендора;
- можно ли из основной конфигурации **достраивать формы вендора кодом** (добавлять поля, кнопки, обработчики);
- встаёт ли полный дистрибутив вендора на УТ11 без урезания;
- отключается ли автообновление модуля;
- работают ли команды пакетного Конфигуратора, на которых строится автоматизация.

Результат шага — заполненная таблица «подтвердилось / нет» и решение: идём по плану или правим план.

## 5. Сценарии проверки

> Где выполнять: **тестовая машина, тестовая база**. Не прод. Проверить, что ты на нужной машине: PowerShell → `$env:COMPUTERNAME`.
> Ключи Конфигуратора в С7 указаны **по памяти** — сверить со справкой установленной платформы (`1cv8.exe /?`, ИТС «Пакетный режим»).

**С1 (Г1). ПМ из основной конфигурации.**
1. В основной конфигурации тестовой базы создать обработку `ДД_подключаемыйМодуль_Тест`, вставить в модуль объекта текст текущего ПМ (`SRC/ERPDiadok/DataProcessors/ДД_подключаемыйМодуль/Ext/ObjectModule.bsl`).
2. В настройках модуля Диадок: «Местонахождение подключаемого модуля» = «Конфигурация», имя — `ДД_подключаемыйМодуль_Тест`.
3. Открыть модуль Диадок, подготовить пакет по документу с договором, где включена индивидуальная настройка подписания (позиция 1).
4. Ожидание: флажок «Запросить подпись контрагента» выставлен по настройке договора — значит, ПМ сработал.

**С2 (Г2). Вызов нового общего модуля из расширения.**
1. В основной конфигурации создать общий модуль `т1кДиадокФормы` (флаг «Сервер»), процедуру `Тест() Экспорт`.
2. В расширении, в форме `ФормаУправляемая`, процедура `ПриСозданииНаСервере` — добавить строку `т1кДиадокФормы.Тест();`.
3. Проверить модули расширения. Ожидание: ошибок нет.

**С3 (Г3). Полный дистрибутив.**
1. На копии тестовой базы заменить текущее расширение полным дистрибутивом 4.61.1 (`TypeDiadok`, собранный в `.cfe`).
2. Открыть модуль, загрузить список документов, открыть карточку контрагента.
3. Ожидание: модуль работает, в журнале регистрации нет ошибок модуля.

**С4 (Г4). Форма вендора достраивается кодом.**
1. В `т1кДиадокФормы` написать `ПриСозданииНаСервере(Форма) Экспорт`: добавить реквизит `шхТест` (Булево) через `Форма.ИзменитьРеквизиты`, флажок на форме в существующую группу, `Элемент.УстановитьДействие("ПриИзменении", "Подключаемый_ШхСобытие")`.
2. В модуле формы `ФормаУправляемая` добавить клиентскую процедуру `Подключаемый_ШхСобытие(Элемент)` с сообщением «сработало», в `ПриСозданииНаСервере` — вызов `т1кДиадокФормы.ПриСозданииНаСервере(ЭтотОбъект)`.
3. Проверить также назначение события самой формы кодом (например «ПриПовторномОткрытии») через `УстановитьДействие`.
4. Ожидание: флажок виден, сообщение появляется, значение не теряется после серверного вызова.

**С5 (Г5). Автообновление.** Найти в настройках модуля управление автообновлением (или по коду `ОбновлениеМодуля_*` — что его включает). Описать, как выключить и как убедиться, что выключено.

**С6. Запрет заимствования из чужого расширения (фиксация факта).** Создать пустое расширение и попробовать заимствовать `Обработка.КонтурЭДО`. Ожидание: объект недоступен.

**С7 (Г6). Команды пакетного Конфигуратора** (Windows, PowerShell; ⚠️ ключи по памяти):
```
1cv8.exe DESIGNER /F "<путь_к_базе>" /N "<пользователь>" /P "<пароль>" /DumpConfigToFiles "<каталог>" -Extension КонтурДиадок
1cv8.exe DESIGNER /F ... /LoadConfigFromFiles "<каталог>" -Extension КонтурДиадок
1cv8.exe DESIGNER /F ... /LoadCfg "<файл.cfe>" -Extension КонтурДиадок
1cv8.exe DESIGNER /F ... /UpdateDBCfg -Extension КонтурДиадок
1cv8.exe DESIGNER /F ... /CheckModules -ThinClient -Server -Extension КонтурДиадок
1cv8.exe DESIGNER /F ... /DumpCfg "<файл.cfe>" -Extension КонтурДиадок
... /Out "<лог.txt>" /DisableStartupDialogs
```
Что делает каждая часть:
- `DESIGNER` — запуск в режиме Конфигуратора.
- `/F` — путь к файловой базе; `/N`, `/P` — пользователь и пароль. Пароль в скриптах не хранить — только переменная окружения.
- `/DumpConfigToFiles` — выгрузить в файлы (только чтение базы).
- `/LoadConfigFromFiles` — загрузить из файлов. ⚠️ **Перезаписывает расширение в базе.**
- `/LoadCfg` — загрузить файл `.cfe`. ⚠️ **Перезаписывает.**
- `/UpdateDBCfg` — применить к базе данных. ⚠️ **Необратимо без бэкапа.**
- `/CheckModules` — синтаксическая проверка модулей для указанных режимов (`-ThinClient`, `-Server`).
- `/DumpCfg` — собрать файл `.cfe`.
- `-Extension` — действие относится к расширению, а не к основной конфигурации.
- `/Out` — файл лога; `/DisableStartupDialogs` — без диалоговых окон.

Отдельно проверить: нужен ли файл `ConfigDumpInfo.xml` при полной загрузке из файлов (ожидание: нет).
