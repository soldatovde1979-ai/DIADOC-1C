## 3. Как запускать Конфигуратор из PowerShell (общий раздел для всех ТЗ)

Где выполнять: **машина архитектора с клиентом 1С**, Windows, PowerShell. Перед запуском убедиться, что это она: `$env:COMPUTERNAME`.

Один раз в сеансе PowerShell задать переменные. Пароль в файлы и в git не пишем.

```powershell
$ErrorActionPreference = 'Stop'
$env:DD_V8   = 'C:\Program Files\1cv8\8.3.27.2130\bin\1cv8.exe'   # путь к платформе
$env:DD_IB   = '<сервер>\<тестовая_база>'                          # например, b-erp-test\erp_uh_test
$env:DD_BUF  = '<сервер>\<буферная_база>'
$env:DD_USER = '<пользователь_с_правами_администратора>'
$env:DD_PWD  = Read-Host 'Пароль' -AsSecureString | ForEach-Object { [Runtime.InteropServices.Marshal]::PtrToStringAuto([Runtime.InteropServices.Marshal]::SecureStringToBSTR($_)) }
```

Разбор:
- `$ErrorActionPreference = 'Stop'` — при любой ошибке PowerShell останавливается, а не идёт дальше.
- `$env:DD_*` — переменные окружения текущего окна PowerShell; после закрытия окна исчезают.
- `Read-Host … -AsSecureString` — спрашивает пароль без показа на экране; следующая часть превращает его в строку для передачи в 1С. Пароль живёт только в памяти этого окна.

Шаблон команды Конфигуратора (все ТЗ используют его):

```powershell
& $env:DD_V8 DESIGNER /S $env:DD_IB /N $env:DD_USER /P $env:DD_PWD /DisableStartupDialogs /Out out\log.txt /DumpResult out\result.txt <КОМАНДА>
Get-Content out\result.txt   # 0 — успех, иначе смотреть out\log.txt
```

Разбор:
- `&` — запустить программу по пути из переменной.
- `DESIGNER` — открыть Конфигуратор, а не пользовательский режим.
- `/S <сервер>\<база>` — какая база (серверный вариант).
- `/N`, `/P` — пользователь и пароль 1С.
- `/DisableStartupDialogs` — не показывать окна при запуске (S008:L1916).
- `/Out <файл>` — писать сообщения Конфигуратора в файл (S008:L1862).
- `/DumpResult <файл>` — записать код результата: 0 — успех (S008:L6542).
- `<КОМАНДА>` — одна из команд ниже. Конфигуратор выполняет её и закрывается.

⚠️ Команды пишут в базу, указанную в `/S`. Перед запуском проверять, что в `$env:DD_IB` — **тестовая** база, не прод.

| Команда | Что делает | Пишет в базу? | Источник |
|---|---|---|---|
| `/DumpConfigToFiles <папка> [-Extension <имя>]` | выгрузить конфигурацию или расширение в XML | нет | S008:L3214-L3240 |
| `/LoadConfigFromFiles <папка> [-Extension <имя>]` | загрузить из XML (полностью заменяет конфигурацию или расширение) | **да** | S008:L3574-L3600 |
| `/DumpCfg <файл.cf\|.cfe> [-Extension <имя>]` | сохранить конфигурацию или расширение в файл | нет | S008:L2234-L2244 |
| `/LoadCfg <файл.cf\|.cfe> [-Extension <имя>]` | загрузить из файла (полностью заменяет) | **да** | S008:L2246-L2264 |
| `/MergeCfg <файл.cf> -Settings <настройки.xml> [-EnableSupport]` | объединить с файлом; `-EnableSupport` — поставить на поддержку | **да** | S008:L2266-L2330 |
| `/UpdateCfg <файл.cf> -Settings <настройки.xml> [-DumpListOfTwiceChangedProperties] [-force]` | обновить конфигурацию поставщика; список «дважды изменённых свойств» = конфликты | **да** | S008:L4610-L4726 |
| `/UpdateDBCfg [-Dynamic+] [-Extension <имя>]` | применить конфигурацию к базе; `-Dynamic+` — сначала обычно, при неудаче — динамически | **да** | S008:L2754-L2810 |
| `/CheckModules -ThinClient -Server [-Extension <имя>\|-AllExtensions]` | синтаксическая проверка модулей | нет | S008:L3794-L3854 |
| `/CheckCanApplyConfigurationExtensions [-Extension <имя>]` | проверка применимости расширения: «сели» ли все зацепки | нет | S008:L4180-L4245 |
| `/ManageCfgSupport -disableSupport` | снять конфигурацию с поддержки (аварийно) | **да** | S008:L4734-L4762 |

## 6. Критерии приёмки

1. Все П1–П17 имеют результат в протоколе.
2. П1, П3, П6 — «да», или принято решение о выходе из схемы.
3. Для каждого «нет» записано, как обходим, и это отражено в реестре или ТЗ.
4. Прод не тронут: все команды выполнялись на тестовой и буферной базах (проверяется по логам — имя базы в `/S`).
