# ТЗ-3. Вынос кастомизаций в расширение конфигурации

| Поле | Значение |
|---|---|
| Пункт плана | Шаг 3 (позиции реестра 17–21) |
| Зависит от | ТЗ-1, ТЗ-2 |
| Кто делает | Совместно: ИИ готовит код обработчиков и текст для переноса; человек выполняет заимствование объектов в Конфигураторе (формы и макеты — бинарные артефакты, скриптом не создаются) |
| Статус | Ожидает согласования |

## Глоссарий (термины этого ТЗ)

| Термин | Что это простыми словами |
|---|---|
| **Расширение конфигурации** | Отдельная «надстройка» над конфигурацией 1С. Хранит наши объекты и доработки отдельно от кода вендора. При обновлении вендора расширение не трогается — его содержимое никуда не девается. |
| **Заимствование формы** | Приём: расширение «подменяет» собой форму вендора. Форма копируется в расширение, и 1С при открытии показывает нашу копию, а не вендорскую. |
| **&Вместо / &После (аннотации)** | Способ перехвата вендорских процедур из расширения. `&После` — «выполни вендорскую процедуру, потом мой код». `&Вместо` — «вместо вендорской процедуры выполни мой код». Механизм официально поддержан 1С. |
| **Конфигуратор** | Среда разработки 1С. Формы и роли нельзя создать текстовым файлом — только через Конфигуратор, поэтому этот шаг не полностью автоматизируется. |
| **Smoke-тест** | Быстрая ручная проверка «основное работает»: открыть форму, отправить пакет, распечатать документ. Не углубляемся в детали — ловим только грубые поломки. |
| **Рег. задание** | Регламентное задание 1С — фоновая операция по расписанию (наш пример: «Автоматизация ЭДО»). |

## 1. Что разработать
Перенос ~60% кастомизаций из модулей вендора в расширение конфигурации `КонтурДиадок` (AddOn):

| Объект | Позиции реестра | Механизм |
|---|---|---|
| Форма `ФормаЭлементаСправочника(Управляемая)` | 18 | Заимствование формы + `&Вместо`/`&После` на вендорские обработчики; ~25 т1к-процедур переносятся целиком |
| Форма `ФормаУправляемая` | 17 | Заимствование; `#Область ДоработкиШХ` → собственные процедуры расширения; вендорские вызовы — `&После` |
| Форма `НастройкаПечатныхФормУправляемая` | 19 | Заимствование; `шх_ОбработатьФорму`, настройки подписания ПФ |
| Форма `НастройкиУправляемая` | 20 | Заимствование; обработчик «хранить в прикреплённых файлах» |
| Форма `ФормаПакетаУправляемая` | 21 | Заимствование; блокировка `ЗапроситьПодписьКонтрагента` |
| Рег. задание «Автоматизация ЭДО» | 3 | Новый объект расширения + общий модуль |
| Макет `т1кПечатьСверкиДиадок` | 2 | Макет расширения |
| Роль `шхДиадок` | 22 | Уже объект расширения — проверка прав |

## 2. Как использовать
- После выноса эти объекты **не трогаются при обновлении вендора** — обновляются только вендорские макеты.
- Каждая заимствованная форма помечается комментарием-шапкой: «Заимствовано из вендора X.XX; переименованные вендорские обработчики — см. список».

## 3. Входы/выходы
- **Вход:** разметка ТЗ-2, текущие модули форм.
- **Выход:** расширение с заимствованными объектами; вендорские модули без ШХ-правок в перенесённых местах.

## 4. Критерии приёмки
- Все позиции 17–21 удалены из модулей вендора и работают из расширения.
- Smoke: открытие карточки контрагента ЭДО, индивидуальные настройки по договору, печатные формы, пакет.
- Сверка ШХ-сумм: блоки из позиций 17–21 исчезли из вендорских файлов, появились в расширении.

## 5. Реестр
| Позиция реестра | Действие |
|---|---|
| 17, 18, 19, 20, 21 | Вынос в расширение |
| 3 | Рег. задание в расширение |
| 22 | Проверка (уже в расширении) |
