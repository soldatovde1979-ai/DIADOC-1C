## 1. Зачем [План: шаг 5, «Зачем»]

Ошибку переноса ловит машина, а человек читает только список конфликтов (my-FT Т-4, Т-5). Отчёт пригоден для стажёра: каждая строка ведёт к позиции реестра.

## 2. Вход [План: шаг 5, «Вход»]

| Что | Где |
|---|---|
| Поставка старого и нового релиза в XML | `SRC/postavka/` — метка `vendor-<старая>` и рабочее состояние |
| Наше расширение | `SRC/ext/` |
| Таблица зацепок | реестр, таблица 2 |
| Эталоны | `tools/checks/reference/expected/` |
| Тестовая база, обновлённая на новый релиз | ТЗ-6 |

## 3. Что сделать [План: шаг 5, «Что делаем»]

Один скрипт `tools/checks/run.ps1 -From vendor-<старая> [-SkipBase]` запускает проверки по порядку и пишет отчёт `out\report\<дата-время>\report.md`. Код выхода 0 — всё зелёное.

| № | Проверка | Как | Красное, если | Что пишет в отчёт |
|---|---|---|---|---|
| 1 | Применимость расширения | `/CheckCanApplyConfigurationExtensions -Extension ДиадокДоработки` (S008:L4180-L4245) | код ≠ 0 | сообщение 1С + метод + позиция (по таблице 2) |
| 2 | Синтаксис модулей | `/CheckModules -ThinClient -Server -AllExtensions` (S008:L3794-L3854) | есть ошибки | модуль, строка, текст ошибки |
| 3 | **Изменились ли методы вендора, за которые мы цепляемся** | Для каждой строки таблицы 2: вынуть текст метода из `SRC/postavka` на метке `-From` и в рабочем состоянии, сравнить (без учёта пробелов в конце строк). Для `&ИзменениеИКонтроль` дополнительно: текст копии в `SRC/ext` без наших `#Вставка` и с восстановленными `#Удаление` = новый текст вендора | текст изменился | метод, позиции, разница «было → стало» (unified diff), подсказка: «перенести вставку `т1кДД <ID>` в новый текст» |
| 4 | Эталоны | `tools/checks/reference.ps1` (ТЗ-1 §3.4) по каталогу, снятому командой «Сформировать эталоны» | есть отличия | случай, файл, «было → стало», позиции |
| 5 | Реестр ↔ код | метки `// т1кДД <ID>` в `SRC/ext` = строки таблицы 2 реестра; у каждой зацепки есть строка и наоборот | расхождение | лишние и недостающие ID |
| 6 | Формы | в `Form.xml` заимствованных форм `SRC/ext` нет элементов, которых нет в форме поставщика (`SRC/postavka`) | есть | форма, элемент — «нарисован вручную, перенести в `т1кДиадокФормы`» (Т-11) |
| 7 | Поставка не тронута руками | список «дважды изменённых свойств» из `/UpdateCfg -DumpListOfTwiceChangedProperties` (ТЗ-6) пуст | не пуст | объекты и свойства — значит, кто-то правил объект поставщика в базе |
| 8 | Новое у вендора | объекты, появившиеся или исчезнувшие в `SRC/postavka` между метками; новые события ПМ (поиск `ИмяСобытия = "` в коде) | — (информационно, не краснит) | список: «посмотреть, не нужна ли доработка» |

Проверки 1, 2 и 4 требуют базы; с `-SkipBase` выполняются только 3, 5, 6, 8 — по репозиторию, без 1С.

Почему проверка 3 нужна при наличии проверки 1: по форуму, на старой платформе зацепка `&ИзменениеИКонтроль` молча отключалась без ошибки (S003:L90-L96; противоречие с S006:L1853-L1873 — план §5.2, П8). Проверка 3 от платформы не зависит.

### 3.1. Эталоны: как снимаются в прогоне

Человек на тестовой базе нажимает в модуле Диадок кнопку «Сформировать эталоны» (ТЗ-1 §3.1) и указывает каталог `out\reference\actual\` — это 1–2 минуты. Скрипт ждёт появления файлов и сравнивает.

Автоматизировать снятие без кнопки (запуск Предприятия с внешней обработкой и параметром) — в ТЗ-6, если получится запустить API вендора вне его формы (R6, вариант 2). Не получится — остаётся кнопка.

### 3.2. Отчёт

`report.md` — по-русски, для стажёра:
1. Итог одной строкой: «ЗЕЛЁНЫЙ — можно в прод» или «КРАСНЫЙ — N конфликтов».
2. Таблица конфликтов: проверка → что случилось → позиция реестра → кто разбирает (позиции 7, 8, 13 и необъяснённые расхождения эталонов — **архитектор**, Т-19; остальное — стажёр по регламенту).
3. Информационный раздел (проверка 8).
4. Пути к логам.

### 3.3. Самопроверка `tools/checks/selftest.ps1`

Скрипт портит копию репозитория во временном каталоге и убеждается, что проверки это ловят:

| Порча | Должна поймать |
|---|---|
| изменить одну строку метода вендора, на который есть зацепка, в `SRC/postavka` | проверка 3 |
| удалить строку из таблицы 2 реестра | проверка 5 |
| добавить в `Form.xml` заимствованной формы элемент | проверка 6 |
| изменить один файл в `expected\X1` | проверка 4 |

Запускается при каждом изменении скриптов проверок и в начале каждого обновления (ТЗ-6, этап 0).

## 5. Критерии приёмки

1. На тестовой базе после ТЗ-4 `run.ps1` — ЗЕЛЁНЫЙ.
2. `selftest.ps1` — каждая порча поймана своей проверкой.
3. С `-SkipBase` скрипт работает без 1С (на любой машине с PowerShell и git) за ≤ 1 мин.
4. Отчёт понятен стажёру без пояснений: проверяет архитектор, читая отчёт с одной намеренной порчей.

## 6. Чего этот шаг не делает

- Не обновляет базу (ТЗ-6).
- Не чинит конфликты — только показывает.
