## Глоссарий (термины этого ТЗ)

| Термин | Что это простыми словами |
|---|---|
| **OneScript (oscript)** | Бесплатный движок для запуска скриптов на языке 1С вне платформы. Ставится на компьютер отдельной программой, запускается из командной строки. Выбран, потому что синтаксис знаком 1С-разработчикам. |
| **Патчер** | Наш скрипт, который берёт чистую выгрузку вендора и автоматически вносит в неё все правки из реестра патчей (ТЗ-5). Ручной перенос ШХ-блоков заменяет собой. |
| **Консольный скрипт** | Программа без окон, запускается командой в терминале с параметрами (`--source`, `--out`). |
| **Код возврата** | Число, которое скрипт отдаёт системе по завершении: 0 — всё хорошо, не 0 — были проблемы. Позволяет встроить скрипт в автоматические цепочки. |
| **BOM** | Служебный маркер кодировки в начале файла (Byte Order Mark). Выгрузка 1С — UTF-8 с BOM; если его потерять, конфигурация не загрузится, поэтому скрипт кодировку проверяет. |
| **Статус патча** | Результат применения одного патча: APPLIED (внесён), NOT_FOUND (якорь не найден), AMBIGUOUS (якорь найден больше одного раза), ALREADY_APPLIED (правка уже стоит). Конфликтом считается всё, кроме APPLIED. |

## 1. Что разработать
Консольный скрипт `tools/patcher/` на OneScript:

```
oscript patcher.os --source <выгрузка вендора> --registry <путь> --out <выход> [--report <отчёт.md>]
```

Функции:
1. Копирование исходной выгрузки в выходной каталог.
2. Применение каждого патча реестра: поиск якоря (имя функции + `search`) → замена на `replace`.
3. Ведение отчёта по каждому патчу: `APPLIED` / `NOT_FOUND` / `AMBIGUOUS` (якорь найден более 1 раза) / `ALREADY_APPLIED`.
4. Подсчёт ШХ-блоков в выходе и сверка с ожидаемым числом из `00-index.json`.
5. Код возврата: 0 — все применено; 1 — есть конфликты (список в отчёте).

## 2. Как использовать
- Штатное обновление: загрузили новую версию вендора → прогнали патчер → открыли отчёт → вручную разобрали только конфликты.
- Работает с текстовой выгрузкой конфигурации (файлы `.bsl`/`.xml`), БД не трогает.

## 3. Ограничения
- Скрипт не правит конфликты и не «угадывает» новые места вставки при изменившемся коде вендора.
- Кодировка входа/выхода — UTF-8 (как в выгрузке), проверка BOM.

## 4. Критерии приёмки
- Прогон на `SRC/TypeDiadok` (4.61.1) + реестр = эталон по MD5 всех патченных модулей.
- Отчёт содержит ровно N=`APPLIED` записей и ноль конфликтов на эталонной версии.

| Позиция реестра | Действие |
|---|---|
