# Спецификация: модуль интеграции Контур.Диадок для 1С (кастомизированный)

> Версия вендора: 4.61.1. Проект: расширение конфигурации (AddOn) + правки вендорских модулей с маркером `ШХ`.
> Документы-основания: [docs/plan.md](plan.md), [docs/tz/](tz/README.md), [docs/Диадок_РеестрИзменений.md](Диадок_РеестрИзменений.md)

## 1. Назначение системы

Модуль обеспечивает интеграцию 1С:УТ11 с сервисом ЭДО Контур.Диадок: отправка/получение
электронных документов, сопоставление номенклатуры и контрагентов, печатные формы, статусы подписания.

## 2. Архитектура

```
Конфигурация 1С (УТ11)
└── Расширение КонтурДиадок (AddOn, версия = версии вендора)
    ├── Заимствованные формы (ФормаЭлементаСправочника, ФормаУправляемая, ...)
    ├── Роль шхДиадок, рег. задание «Автоматизация ЭДО»
    └── [план] вынос всех кастомизаций форм из модулей вендора
└── Обработка КонтурЭДО (вендор)
    └── Templates: КонтурДиадокЯдро, КонтурДиадокХранениеДанных, КонтурДиадокГенерацияXML, ...
        ← здесь живут ШХ-правки (цель: свести к минимуму)
└── Обработка ДД_подключаемыйМодуль (наш хук, официальный механизм вендора)
    └── события: ПодготовитьПакет, ПодготовитьЭлектронныйДокумент, ...
└── [план] tools/patcher — скрипт-патчер + реестр патчей
└── [план] tools/tests — тест-скрипт сверки с эталоном
```

## 3. Кастомизации (маркер ШХ)

- Разметка: `// ШХ <ID> BEGIN ... // ШХ <ID> END` (формат — ТЗ-2).
- Реестр: 23 позиции, 205 блоков. Категории действий:
  - **хук** — остаётся в `ДД_подключаемыйМодуль`;
  - **расширение** — заимствованные формы/объекты;
  - **патч** — машинночитаемая запись для скрипта-патчера (якорь = функция вендора + SEARCH/REPLACE).
- Четыре тематических блока: настройки по договорам (`Договор1С`), автоматизация ЭДО
  (рег. задание, хранение в прикреплённых файлах), единицы измерения в XML (`НаимЕдИзм`),
  запрос подписи контрагента (`ЗапрашиватьОтветнуюПодпись`).

## 4. Процесс обновления (целевой)

1. Чистая выгрузка новой версии вендора → 2. скрипт-патчер → 3. отчёт конфликтов →
4. тест-скрипт (сверка с эталоном) → 5. загрузка в конфигурацию + расширение → 6. smoke → 7. фиксация эталона.
Подробно: [docs/tz/TZ-8-reglament.md](tz/TZ-8-reglament.md). Целевое время: ≤ 1–1,5 ч.

## 5. Критичные места (проверять в первую очередь при обновлении)

| Место | Почему |
|---|---|
| `КонтурДиадокГенерацияXML` (НаимЕдИзм, ~20 вставок) | Наибольшая плотность правок |
| `КонтурДиадокЯдро` + `КонтурДиадокХранениеДанных` (Договор1С) | Связанная пара — менять только вместе |
| `ПодключаемыйМодуль_СовместимыеПараметры` | Точка входа всех событий хука |

## 6. Ограничения и правила

1. Прямые правки вендорских модулей запрещены — только через реестр патчей.
2. Новая кастомизация: сначала ищем событие хука, потом расширение, патч — последнее.
3. Секреты (логины/пароли Диадок) — только через настройки модуля, в коде и репозитории запрещены.
4. Любая правка сопровождается обновлением реестра и эталона.
