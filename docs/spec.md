# Спецификация: модуль интеграции Контур.Диадок для 1С:УТ11 (кастомизированный)

> Версия: 2.2 · 08.10.2026. Версия вендора: 4.61.1.
> Документы-основания: [plan.md](plan.md), [tz/](tz/README.md), [Диадок_РеестрИзменений.md](Диадок_РеестрИзменений.md), [my-FT.md](my-FT.md).
> Отмечено: **[сейчас]** — текущее состояние; **[цель]** — после исполнения plan v3.

## 1. Назначение

Интеграция 1С:УТ11 с сервисом ЭДО Контур.Диадок: отправка и получение электронных документов, сопоставление
номенклатуры и контрагентов, печатные формы, статусы подписания. Наши доработки: настройки ЭДО в разрезе договоров,
автоматизация ЭДО, единицы измерения из входящих документов, запрос подписи контрагента, хранение в прикреплённых файлах.

## 2. Архитектура

```
Основная конфигурация УТ11 (обновлением вендора не затрагивается)
├── т1кДиадокСервер, т1кДиадокДоговора, т1кСверкаОказанныхУслуг …     [сейчас] наша логика и данные
├── РегистрыСведений.т1кДиадок_НастройкиДоговоров                      [сейчас] настройки по договорам
├── РегистрыСведений.т1кЗначенияПроизвольныхПараметров                 [сейчас] параметры автоматизации
├── Обработка ДД_подключаемыйМодуль (ПМ)                               [цель] перенесена из расширения
└── т1кДиадокФормы / т1кДиадокФормыКлиент / т1кДиадокМодули            [цель] программное изменение форм, наши процедуры

Расширение КонтурДиадок (AddOn) — поставляется вендором, заменяется при обновлении
├── Обработки КонтурЭДО, КонтурДиадокЯдро, …ХранениеДанных, …ГенерацияXML, …
│     [сейчас] ≈2830 строк наших правок в 14 файлах
│     [цель]   точки вызова // ШХ <ID> + встроенная дельта (поз. 4–13, 15)
├── Роль шхДиадок                                                       наша, остаётся
└── Обработка ДД_подключаемыйМодуль                                     [сейчас] здесь; [цель] удалена
```

**Как вендор вызывает ПМ.** Ядро читает настройку «Местонахождение подключаемого модуля»: «Конфигурация» —
`Обработки[Имя].Создать()`, «Диск» — файл, «1С» — справочник. Затем вызывает `ОбработатьСобытие` с именем события.
События 4.61.1: `ВыполнитьРегламентныеДействия`, `ВыполнитьТребуемоеДействие`, `ЗаполнитьРеквизитыДокумента`,
`ЗаполнитьСписокДополнительныхКнопок`, `ЗаполнитьТаблицуСопоставленияНоменклатуры`, `НажатиеДополнительнойКнопки`,
`ОбновитьКомментарийДокументаУчета`, `ПечатнаяФормаДокумента`, `ПодготовитьПакет`, `ПодготовитьЭлектронныйДокумент`,
`ПодготовитьЭлектронныйДокументПоВнешнейПечатнойФорме`, `ПодписатьДанные`, `ПолучитьКоличествоДокументовЗаПериод`,
`ПолучитьНастройкиДополнительныхКолонокСпискаДокументов`, `ПолучитьСертификатВBase64`, `ПолучитьСертификатыДляШифрования`,
`ПолучитьТекстЗапросаДляСпискаПакетовНаОтправкуПоМассивуВидовПакетов`, `ПослеАнализаПакета`, `ПослеОбновленияСпискаДокументов`,
`ПослеОбработкиЛентыСобытий`, `ПослеОтправкиПакета`, `ПослеПодготовкиПакета`, `ПослеУстановкиСтатусаДокумента`,
`ПравилаСопоставленияДокумента`, `ПроверитьПодпись`, `ПровестиАнализДокумента`, `РасшифроватьДанные`, `УстановитьУсловноеОформление`.

**Формы вендора [цель].** `Form.xml` не меняются. Наш код добавляет реквизиты, элементы, команды и обработчики
при создании формы. В модуле формы — шаблон диспетчеров и точки вызова (ТЗ-3 §2.4).

## 3. Кастомизации

- Реестр: 26 позиций, слои 1–4 ([реестр](Диадок_РеестрИзменений.md)).
- Разметка в вендорском коде [цель]: только точки дельты — `// ШХ <ID>` или блок `// ШХ <ID> {` … `}` (ТЗ-4 §2.1).
  ID = `<позиция>-<NN>`, каждый в табл. 3 реестра.

## 4. Процесс обновления [цель]

`update.ps1`: подготовка → сверка прода с последним релизом → импорт дистрибутива в ветку `vendor` → слияние →
проверки (инварианты, компиляция, эталонные XML) → сборка `.cfe` → журнал. Затем вручную: бэкап, загрузка, smoke.
Регламент — `docs/update-checklist.md` (ТЗ-7). Цель — ≤ 1–1,5 ч в спокойный релиз.

## 5. Критичные места

| Место | Почему |
|---|---|
| `КонтурДиадокГенерацияXML` (поз. 7) | Новые функции разбора у вендора остаются без нашей единицы → сигнатурный контроль Б3 |
| `КонтурДиадокЯдро` + `КонтурДиадокХранениеДанных` (поз. 8 + 13) | Сквозной `Договор1С`; менять только парой |
| `ПодключаемыйМодуль_СовместимыеПараметры` (поз. 9) | Точка входа всех событий ПМ |
| Автообновление модуля (`КонтурДиадокАпдейтКлиент`) | Может поставить чистую версию в обход процесса |

## 6. Правила

1. Новая доработка: событие ПМ → наш модуль `т1кДиадок*` + точка вызова (формы — только программно) → встроенная дельта с ID.
2. Вендорский код меняется только в точках дельты с ID и строкой в табл. 3 реестра.
3. Секреты (логины и пароли Диадок, пароли ИБ) — только настройки модуля и переменные окружения. В коде и репозитории запрещены.
4. Выгрузки `vendor` и основной ветки — одной версией платформы.
