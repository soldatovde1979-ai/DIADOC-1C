# ТЗ-7. Приёмка

| Поле | Значение |
|---|---|
| Версия | 1.0 · 07.10.2026 |
| Шаг плана | 8 |
| Зависит от | все |
| Кто делает | Человек — обновления по регламенту; ИИ — помощь в разборе, актуализация реестра и журнала |

## 1. Процедура

1. **База.** Если до ввода новой схемы выйдет релиз, обновление по старой схеме замеряется по шагам (журнал).
   Иначе база — оценка «8 ч» с этой пометкой.
2. **Контрольные обновления.** 2–3 реальных обновления по регламенту с `update.ps1`. В журнале — тип релиза.
   Хотя бы одно, по возможности, затрагивает `ГенерацияXML` или `Ядро` в местах дельты. Если такого релиза нет,
   засчитывается ретро-прогон на версии, где это было.
3. **Чистый исполнитель.** Одно из обновлений (или ретро-прогон) — исполнителем без знания истории (TZ-6 §2).

## 2. Метрики

См. plan §7 (единица — точка дельты или шаг регламента):

| Метрика | Цель |
|---|---|
| Время, сумма по шагам | ≤ 1–1,5 ч в спокойный релиз; фиксируется и для «тяжёлого» |
| Точки дельты, перенесённые слиянием без ручной правки | ≥ 90% |
| Конфликтные точки | ≤ 3 |
| Необъяснённые расхождения эталонных XML | 0 |
| Ошибки компиляции после сборки | 0 |
| Регрессии, найденные пользователями | 0 |

## 3. Выход

- Журнал с 2–3 строками и итоговое решение: ввод в эксплуатацию / доработка (что именно).
- Обновлённая табл. 3 реестра, эталоны, теги `release/*`.
- Отметки `[x]` в `docs/my-FT.md` по выполненным требованиям.
