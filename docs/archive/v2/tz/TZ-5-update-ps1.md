# ТЗ-5. Команда обновления `update.ps1`

| Поле | Значение |
|---|---|
| Версия | 1.0 · 07.10.2026 |
| Шаг плана | 6 |
| Зависит от | TZ-0 (С7), TZ-1, TZ-4 |
| Кто делает | ИИ — скрипт целиком; человек — конфигурация путей, запуск |
| ОС / оболочка | Windows, PowerShell 5.1+ |

## Глоссарий

| Термин | Что это |
|---|---|
| **Обёртка** | Один скрипт, который по порядку выполняет все шаги обновления, меряет время и останавливается на первом «стоп». |
| **Ранний прогон (`-DryRun`)** | Шаги 1–5 без сборки релиза. Запускается на каждом релизе вендора как индикатор, даже если ставить не собираемся. |
| **Служебная ИБ / тестовая ИБ** | Служебная — чистая, для выгрузки дистрибутива. Тестовая — копия прода, для проверок. Прод скрипт не меняет. |

## 1. Что разработать

`tools/update.ps1` + `tools/update.config.psd1` (пути к ИБ, к `1cv8.exe`, имя расширения). Паролей нет: только
переменная окружения `DIADOC_IB_PASSWORD`.

```
update.ps1 -Cfe <путь к новому .cfe> -Version <x.y.z> [-DryRun] [-From <шаг>]
```

| Шаг | Действие | Стоп, если |
|---|---|---|
| 1 Подготовка | Рабочее дерево git чистое; версия платформы = зафиксированной в конфиге; есть `1cv8.exe` | что-то не так |
| 2 Сверка прода | Выгрузка расширения из **копии** прода (или `.cfe`, выгруженного администратором) и сравнение с последним тегом `release/*` | есть отличия (Р1) — правку из прода сначала оформить в git |
| 3 Импорт вендора | `.cfe` → служебная ИБ → выгрузка → коммит в `vendor`, тег `vendor/<v>` (если тег уже есть — пропуск) | ошибка выгрузки |
| 4 Слияние | Ветка `update/<v>` от основной, `git merge vendor/<v>` | конфликты → отчёт со списком файлов и ID точек дельты в них, код 1; после ручного разбора — `-From 5` |
| 5 Проверки | `invariants.ps1` (Б1–Б5), `compile.ps1` (А1), `reference.ps1` (А2) | любое нарушение |
| 6 Сборка | Выгрузка `.cfe` из тестовой ИБ в `out/<v>/`, тег `release/<v>-<n>` | ошибка сборки |
| 7 Журнал | Строка в `docs/update-journal.md`: время каждого шага, число конфликтов и ID, нарушения, тип релиза (вводит человек) | — |

С `-DryRun` выполняются шаги 1–5. Ветка `update/<v>` удаляется, тег `vendor/<v>` остаётся.

## 2. Требования к скрипту

- `$ErrorActionPreference = 'Stop'`, `Set-StrictMode -Version Latest`.
- Коды возврата: 0 — готово; 1 — стоп по содержанию (конфликт, нарушение проверок, отличие прода); 2 — сбой выполнения.
- Идемпотентность: повторный запуск того же шага не дублирует коммиты и теги; `-From` продолжает с шага.
- Каждый шаг пишет время начала и конца в `out/<v>/log.txt`.
- Итоговая строка: `МОЖНО СТАВИТЬ` или `СТОП: <причина>`.
- Прод не трогается. Загрузка в прод — ручной шаг регламента (TZ-6).

## 3. Критерии приёмки

1. Полный прогон на 4.61.1 («обновление» на ту же версию) даёт `МОЖНО СТАВИТЬ` и 0 конфликтов.
2. Ретро-прогон на версии новее (если есть) проходит до шага 4 или 5 и даёт понятный отчёт.
3. Повторный запуск без изменений ничего не дублирует.
4. Искусственное отличие «прода» останавливает скрипт на шаге 2.
