## Глоссарий

| Термин | Что это |
|---|---|
| **Встроенная дельта (слой 3)** | Наши изменения внутри вендорского кода, которые нельзя заменить точкой вызова: новый параметр функции, изменённое выражение. Переносятся слиянием git. |
| **Точка дельты, ID** | Одно место нашего изменения в вендорском файле, ID `<поз>-<NN>`, например `07-03`. Единица учёта в метриках. |
| **Сигнатура** | Имя функции и список её параметров. Если мы добавили параметр (поз. 7, 8, 13), новые вызовы вендора его не передадут — это ловит сигнатурный контроль (TZ-4 Б3). |
| **Контекст договора** | Альтернатива сквозному параметру `Договор1С`: значение договора хранится в переменной модуля на время обработки одного документа, функции чтения настроек берут его оттуда. |

## 1. Что разработать

### 1.1. Единая разметка точек дельты (только слои 2 и 3, не все 205 блоков)

```bsl
<код>  // ШХ 07-03            — однострочная точка
// ШХ 08-05 {                — начало многострочной
<код>
// ШХ 08-05 }                — конец
```
- Удаление вендорской строки: строка остаётся закомментированной с пометкой `// ШХ <ID> удалено:` (поз. 4, 7).
- Старые маркеры (`// + ШХ`, `// - ШХ`, ссылки на карточки т1к) в точках дельты заменяются на ID.
  Автор, дата и ссылка на задачу переносятся в реестр (табл. 3).
- Вне точек дельты маркеров `ШХ` в вендорских файлах нет. Проверка — TZ-4 Б1.

### 1.3. Сокращение тел

Любая вставка длиннее 3 строк, которую можно оформить вызовом `т1кДиадокМодули`, переносится туда.
Остаются только выражения, неотделимые от вендорского кода (параметры вызовов, изменённые присваивания).

## 2. Решения, нужные от человека

Пункты §1.2 с колонкой «решает: человек». До решения позиция остаётся в текущем виде, размечается ID
и попадает под сигнатурный контроль. Решения записываются в `docs/my-FT.md`.

## 3. Входы / выходы

| | Что |
|---|---|
| Вход | Основная ветка после TZ-2; результаты С5, С8, С9 |
| Выход | Финальная дельта слоя 3 с разметкой; **табл. 3 реестра** — все ID: файл, функция, суть, автор/дата/задача, слой, правило проверки |

## 4. Критерии приёмки

1. Каждая точка дельты имеет ID и строку в табл. 3; каждая строка табл. 3 найдена в коде (TZ-4 Б1).
2. Решения §1.2 приняты и записаны (или явно отложены с пометкой «оставлено как есть»).
3. Компиляция и эталонные XML — без расхождений.
4. Объём дельты в вендорских файлах (строк `+`/`−` в `git diff vendor`) записан в реестр. Это база для метрик.
