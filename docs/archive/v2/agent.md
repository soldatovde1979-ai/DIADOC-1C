> Версия: 2.0 · 07.10.2026 (под plan v2).
> Если ты (агент) начинаешь новую сессию — прочитай этот файл первым.

## 1. Что за проект

Кастомизированный модуль Контур.Диадок для 1С:УТ11, версия вендора 4.61.1. Вендор поставляет модуль как расширение
`КонтурДиадок` (AddOn). Наши правки — внутри него и в основной конфигурации (`т1к*`). Цель — обновление за 1–1,5 ч
(см. [docs/plan.md](docs/plan.md)).

## 3. Жёсткие правила

1. **Иерархия решений:** событие ПМ (`ДД_подключаемыйМодуль`) → наш модуль `т1кДиадок*` + точка вызова →
   встроенная дельта в вендорском коде — последнее средство.
2. **Формы вендора — только программно.** `Form.xml` вендора не меняем. Реквизиты, элементы, команды и обработчики
   добавляет `т1кДиадокФормы` при создании формы.
3. **Вендорский код** меняется только в точках дельты: `// ШХ <ID>` или блок `// ШХ <ID> {` … `}`. Каждый ID —
   строка в табл. 3 реестра. ID в сообщении коммита.
4. **Ветка `vendor`** — только чистые выгрузки дистрибутива. Наш код туда не попадает. Историю не переписывать.
5. **Согласование:** перед изменением >1 файла или логики — план и ожидание «ок».
6. **Никакого попутного рефакторинга:** не переименовывать, не форматировать, не удалять «мёртвый» код.
7. **Не выдумывать сущности:** API, пути, имена функций — только из открытых файлов или ТЗ.
   Нужны данные — вывести: `Для генерации ответа необходимы данные:` + список.
8. **Секреты** — только ENV и настройки модуля. В коде и репозитории запрещены.
9. **Отчёт после правок** — строго блоком: «Внесенные изменения / Намеренно не тронуто / Потенциальные риски».

## 4. Как проверять свою работу

- До появления скриптов ТЗ-4: `git diff` по вендорским файлам — только точки дельты с ID; `Form.xml` вендора не изменены.
- После появления: `tools/checks/invariants.ps1` (Б1–Б5) и, на стороне человека, компиляция и эталонные XML.
- Код `.bsl`, написанный ИИ, считается непроверенным до компиляции в тестовой ИБ.

## 5. Структура репозитория

```
SRC/ERPDiadok/            — текущая кастомизированная выгрузка расширения [до ТЗ-1]
SRC/TypeDiadok/           — чистый дистрибутив 4.61.1 [до ТЗ-1]
SRC/КонтурДиадок/         — [цель ТЗ-1] единая выгрузка: в ветке vendor — дистрибутив, в основной — с нашей дельтой
SRC/ОсновнаяКонфигурация/ — [цель ТЗ-2] тексты наших объектов основной конфигурации (ПМ, т1кДиадокФормы*, т1кДиадокМодули)
docs/my-FT.md             — требования
docs/plan.md, docs/tz/    — план и ТЗ
docs/Диадок_РеестрИзменений.md — реестр позиций и ID точек дельты
tools/checks/             — [цель ТЗ-4] проверки
tools/update.ps1          — [цель ТЗ-5] команда обновления
```

## 6. Стиль кода 1С

- Язык — русский (имена переменных и процедур), комментарии в стиле вендора.
- Собственные объекты и процедуры — префикс `т1к` (основной) или `шх` (исторически в расширении). Не смешивать с вендорскими именами.
- Отступы — табуляция.
- Скрипты: PowerShell 5.1+, `$ErrorActionPreference = 'Stop'`, коды возврата 0 / 1 / 2.
