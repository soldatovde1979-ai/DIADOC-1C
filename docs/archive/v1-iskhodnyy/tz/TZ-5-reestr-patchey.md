# ТЗ-5. Реестр патчей для автовыгрузки

| Поле | Значение |
|---|---|
| Пункт плана | Шаг 5 (позиции 4–8, 10–13, 15) |
| Зависит от | ТЗ-2, ТЗ-3, ТЗ-4 (только после них известен остаток) |
| Кто делает | ИИ (я) — составление JSON-патчей сравнением эталона с чистым дистрибутивом; человек — ревью реестра |
| Статус | Ожидает согласования |

## Глоссарий (термины этого ТЗ)

| Термин | Что это простыми словами |
|---|---|
| **Патч** | Описание одной точечной правки кода вендора в виде «найди такой-то текст → замени на такой-то». Хранится в JSON-файле, а не в коде вендора. |
| **Реестр патчей** | Папка с такими JSON-файлами — полное описание всех наших вставок, которые нельзя вынести в расширение или хуки. Это «инструкция для робота», как воспроизвести наши правки на чистом коде вендора. |
| **Якорь** | Уникальная примета места вставки: имя вендорской функции + кусок окружающего кода (`search`). По якорю скрипт находит, куда именно вносить правку. Якорь должен встречаться в файле ровно один раз. |
| **SEARCH / REPLACE** | Два текста внутри патча: SEARCH — что ищем (якорь), REPLACE — что вставляем на его место (тот же текст + наш ШХ-код). Механика «найти и заменить». |
| **JSON** | Текстовый формат данных «ключ — значение», читается и человеком, и скриптом. |
| **vendorVersion** | Поле патча: версия вендора, на которой проверена точность якоря (сейчас 4.61.1). Если вендор сменил код — якорь перепроверяется на новой версии. |
| **00-index.json** | Оглавление реестра: сколько патчей, к каким файлам, сколько вставок ожидается. По нему тесты сверяют полноту применения. |

## 1. Что разработать
Формат и наполнение машинночитаемого реестра патчей `tools/patcher/registry/`:

```
registry/
  00-index.json          # индекс: id → файл → число вставок → целевой модуль
  04-vyzovy-pm.json      # по позиции реестра
  07-generaciya-xml.json
  08-yadro-dogovor1s.json
  ...
```

Формат одного патча:

```json
{
  "id": "08-1",
  "registry": 8,
  "module": "SRC/ERPDiadok/DataProcessors/КонтурДиадокЯдро/Ext/ObjectModule.bsl",
  "anchor": "Функция НастройкиДокументов_НастройкиДокументовНаОтправку",
  "search": "текст для поиска (уникальный контекст вендора)",
  "replace": "текст с вставкой ШХ",
  "vendorVersion": "4.61.1",
  "comment": "Сквозной параметр Договор1С"
}
```

## 2. Как использовать
- Патчер (ТЗ-6) применяет патчи к чистой выгрузке вендора автоматически.
- Новая кастомизация = новый JSON-файл в реестре + прогон теста (ТЗ-7). Никаких правок «напрямую в модуле».

## 3. Состав (по реестру)
| Позиция | Патчей (оценка) | Примечание |
|---|---|---|
| 4 (ВызовыПМ) | 1 | Стабильный якорь |
| 5 (ИнтеграцияУТ11) | 1 | Уточнить актуальность у автора |
| 6 (СтандартУФ) | 1 | т1кПараметры |
| 7 (ГенерацияXML) | ~20 | Группа НаимЕдИзм; сверять с новой версией вендора |
| 8 (Ядро, Договор1С) | ~15 | Группа |
| 10 (Ядро, контракт) | 4 | Вставки строк |
| 11 (Ядро, КС расширения) | 1 | Проверять смысл на каждом мажоре |
| 12 (Ядро, пакеты/ПФ) | ~8 | Остаток после ТЗ-4 |
| 13 (ХранениеДанных, Договор1С) | ~6 | Пара к №8 |
| 15 (ХранениеДанных, РежимПользователя) | 2 | |

Итого ≈ 40 патчей.

## 4. Критерии приёмки
- Каждый патч применяется к чистому дистрибутиву 4.61.1 и даёт байт-в-байт совпадение с эталоном своего участка.
- `00-index.json` консистентен: число патчей = сумме счётчиков.

## 5. Реестр
| Позиция реестра | Действие |
|---|---|
| 4–8, 10–13, 15 | Оформление в реестр патчей |
| 16 | Частично: вставки — патч, процедура — хук (ТЗ-4) |
