| Поле | Значение |
|---|---|
| Пункт плана | Шаг 2 |
| Зависит от | ТЗ-1 |
| Кто делает | ИИ (я) — правка комментариев ШХ по файлам, человек — контроль сверки |
| Статус | Ожидает согласования |

## Глоссарий (термины этого ТЗ)

| Термин | Что это простыми словами |
|---|---|
| **Нормализация** | Приведение всех ШХ-комментариев к одному одинаковому виду. Сейчас блоки размечены кто во что горазд: где-то `// ШХ`, где-то `// + ШХ`, где-то вообще без END. После нормализации — один канонический формат для всех. |
| **Канонический формат** | Эталонный вид разметки: `// ШХ <ID> BEGIN | ...` и `// ШХ <ID> END`. Канонический = единственно правильный, по которому скрипты могут однозначно найти начало и конец блока. |
| **ID блока** | Адрес блока: номер позиции реестра + порядковый номер внутри неё (например `07-3` = позиция 7, блок 3). По ID любой блок можно найти и в коде, и в реестре. |
| **Машиночитаемый** | Понятный для программы-скрипта без «догадок». Формат `BEGIN/END` с фиксированной структурой скрипт может разобрать автоматически; свободный комментарий — нет. |
| **Байт-в-байт** | Полное посимвольное совпадение. Проверка «код внутри блока не изменился ни на один символ». |
| **doc-only блок** | Блок, внутри которого только комментарии, без исполняемого кода. На логику не влияет, в реестр патчей не включается. |

## 1. Что разработать
Единый машинночитаемый формат всех кастомизационных блоков в коде:

```bsl
// ШХ <ID> BEGIN | <автор> | <дата> | <задача т1к>
<оригинальный код без изменений>
// ШХ <ID> END
```

- `<ID>` — номер позиции реестра (1–23) + порядковый номер блока внутри позиции (например `07-3`).
- Формат описан в `docs/tz/shx-markup-spec.md` (создаётся этим ТЗ).

## 2. Как использовать
- Скрипт-патчер (ТЗ-6) ищет блоки строго по маркерам `BEGIN/END`, якорем служит имя функции вендора.
- Тест-скрипт (ТЗ-7) сверяет количество и содержимое блоков по ID.

## 3. Работы
| № | Работа | Примечание |
|---|---|---|
| 2.1 | Присвоить каждому из 205 блоков ID по реестру | Автопоиск + ручная классификация |
| 2.2 | Нормализовать неканоничные блоки: `// ШХ` без `- ШХ`, блок «TODO: переделать» (ФормаУправляемая 2411), блоки-комментарии без кода | Блоки-комментарии → пометить «doc-only», в реестр не включать |
| 2.3 | Проверить парность BEGIN/END и посчитать суммы до/после | Код внутри — байт-в-байт |

## 4. Критерии приёмки
- Сумма блоков до нормализации = после (205 → 205).
- Каждый блок однозначно мапится на позицию реестра.
- Ноль изменений исполняемого кода.

## 5. Реестр
| Позиция реестра | Действие |
|---|---|
| Все, кроме №1, 22, 23 (уже в целевом виде) | Разметка нормализуется |
