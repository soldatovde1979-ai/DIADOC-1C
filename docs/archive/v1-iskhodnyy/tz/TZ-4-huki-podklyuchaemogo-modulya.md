# ТЗ-4. Перенос логики в хуки (ДД_подключаемыйМодуль)

| Поле | Значение |
|---|---|
| Пункт плана | Шаг 4 (позиции 1, 2, 9, 14, 16, 23) |
| Зависит от | ТЗ-1, ТЗ-2 |
| Кто делает | ИИ (я) — правки кода в ДД_подключаемыйМодуль и удаление ветвлений из модулей вендора (текстовые файлы); человек — контроль smoke-теста |
| Статус | Ожидает согласования |

## Глоссарий (термины этого ТЗ)

| Термин | Что это простыми словами |
|---|---|
| **Хук (hook, «крючок»)** | Точка, где вендор сам вызывает наш код. Вендор в определённых местах «спрашивает»: есть ли у тебя своя логика? — и выполняет то, что вернёт наш модуль. Наш хук — обработчик `ДД_подключаемыйМодуль`. |
| **ДД_подключаемыйМодуль** | Наш отдельный модуль-обработчик, который вендор вызывает в официальных событиях (см. ниже). Единственное место, где живёт логика «поверх» вендора в этом слое. |
| **Событие вендора** | Официально объявленная вендором точка вызова, например `ПодготовитьПакет`. Список и сигнатуры — в макете вендора `СобытияПодключаемогоМодуля` и его документации. При обновлении вендора события сохраняются — это самый надёжный слой кастомизации. |
| **Ветвление ШХ** | Участок вида `Если т1к_условие Тогда ... КонецЕсли;` внутри вендорской функции. Вместо таких вставок логика переносится в хук, и вендорская функция остаётся чистой. |
| **Smoke-тест** | Быстрая ручная проверка «основное работает» (см. ТЗ-3). |

## 1. Что разработать
Концентрация всей логики, покрываемой официальными событиями вендора, в [`ДД_подключаемыйМодуль`](../../SRC/ERPDiadok/DataProcessors/ДД_подключаемыйМодуль/Ext/ObjectModule.bsl):

| Событие | Что переносим | Позиция реестра |
|---|---|---|
| `ПодготовитьЭлектронныйДокумент` | Проброс `т1кОтправитель/т1кПолучатель`, т1к-параметры | 9 |
| `ПодготовитьЭлектронныйДокументПоВнешнейПечатнойФорме` | Запрос подписи контрагента (уже там — проверить полноту) | 1 |
| `ПодготовитьПакет` | Доп. печатные формы, имя файла документа | 12 (частично) |
| Команда печати | ПФ «Сверка (ШХ)» — обработчик из расширения | 2 |
| Хранение данных | Вызовы `Документы_ЗаписатьДанныеХранилища_ПрикрепленныеФайлы` остаются в ХранениеДанных, ветвление минимизируется | 14 |
| Регистрация хука | Сверка с макетом `СобытияПодключаемогоМодуля` вендора | 23 |

## 2. Как использовать
- `ДД_подключаемыйМодуль` — официальный механизм вендора ([документация](https://developer.kontur.ru/Docs/Diadoc_UM/proc/pm/Podgotovka_Paketa_Dlya_Otpravki.html)), выживает при обновлениях без правок.
- Правило: любая новая кастомизация сначала проверяется «а есть ли событие?»; только при отсутствии — патч.

## 3. Критерии приёмки
- Ветвления `// + ШХ` внутри `КонтурДиадокЯдро` (позиции 9, 12) удалены, логика живёт в хуках.
- Smoke: отправка пакета с запросом подписи и доп. ПФ через хук, без правок вендорских модулей.

## 4. Реестр
| Позиция реестра | Действие |
|---|---|
| 1 | Не трогать (уже хук) |
| 2, 9, 14, 16, 23 | Перенос/минимизация в хуки |
| 12 (частично) | Убираемые хуком вставки — пометить в реестре |
