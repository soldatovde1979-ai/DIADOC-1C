| Поле | Значение |

## Глоссарий (термины этого ТЗ)

| Термин | Что это простыми словами |
|---|---|
| **Регламент** | Пошаговая инструкция «делай раз, два, три» — настолько подробная, чтобы любой инженер выполнил обновление без знания истории проекта. |
| **Чек-лист** | Список действий с отметками «выполнено». В отличие от регламента — без подробных пояснений, только порядок и контрольные точки. |
| **Конфликт патча** | Скрипт не смог внести правку, потому что вендор изменил код в месте якоря (NOT_FOUND/AMBIGUOUS). Конфликт не чинится автоматически — разбирается человеком по реестру. |
| **Откат** | Возврат к предыдущей работающей версии: работаем на старой версии вендора + старом эталоне, пока конфликт не разобран. Регламент описывает, когда откат обязателен. |
| **Ревью** | Проверка изменений вторым человеком перед принятием в основную ветку. Правило этого проекта: патч без пройденного теста (ТЗ-7) не принимается. |
| **vendorVersion** | Версия вендора, на которой проверены якори патчей. Хранится в каждом патче (ТЗ-5); после успешного обновления — обновляется. |

## 1. Что разработать
Документ `docs/update-checklist.md`, разделы:

1. **Регламент обновления** (целевой — ≤1–1,5 ч):
   1. Загрузить новую версию вендора в чистый каталог.
   2. Прогнать патчер (ТЗ-6) → отчёт.
   3. Конфликты (`NOT_FOUND/AMBIGUOUS`) — ручной разбор по реестру.
   4. Прогнать тест-скрипт (ТЗ-7) → PASS.
   5. Загрузить в конфигурацию + подключить расширение.
   6. Smoke-тест по чек-листу.
   7. Обновить `vendorVersion` в реестре, пересобрать эталон.
2. **Правила ведения реестра патчей**: новая доработка = JSON в реестре + отметка в реестре кастомизаций; запрет прямых правок вендорских модулей.
3. **Матрица ответственности**: кто патчит, кто проверяет, кто релизит.
4. **Журнал обновлений**: таблица дата / версия вендора / конфликты / время / исполнитель.

## 2. Как использовать
- Единый чек-лист для любого инженера; время по шагам фиксируется для контроля метрики.

## 3. Критерии приёмки
- Документ покрывает 100% шагов обновления; по нему можно выполнить обновление без знания истории проекта.
