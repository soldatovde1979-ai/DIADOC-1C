# Реестр изменений модуля Контур.Диадок: что и как меняем

> Версия: 4.0 · 09.10.2026 · К [плану v4](plan.md), [ТЗ](tz/README.md). Предыдущая версия (3.1) — [docs/archive/v3/](archive/v3/Диадок_РеестрИзменений.md).
> **Это главный документ по доработкам.** По каждой позиции здесь записано: зачем она, где сидит у вендора и как переносится. План (§4) даёт обзор, ТЗ-3 и ТЗ-4 — порядок работ. При расхождении прав реестр (my-FT Р-9).

## Как читать

- **Позиция** — одна наша доработка с понятной целью. Номера 1–26 не меняются (на них ссылаются R1, эталоны, smoke).
- **Мест** — сколько мест в коде вендора она занимает сейчас (опись [R1](research/R1-opis-delty.md), прод `SRC/ERPDiadok`, вендор 4.61.1).
- **Методы вендора** — где именно стоят наши правки. Файл вендора сокращён: `Ядро` = обработка `КонтурДиадокЯдро`, `ХД` = `КонтурДиадокХранениеДанных`, `ГенXML` = `КонтурДиадокГенерацияXML`, `ЭДО` = `КонтурЭДО`, `СтУФ` = `КонтурДиадокСтандартУФ`, `СтУФ_УТ11` = `КонтурДиадокСтандартУФ_Модуль_ИнтеграцияУТ11`, `СтУФ_Унив` = `КонтурДиадокСтандартУФ_Модуль_ИнтеграцияУниверсальный`, `ИнтУТ11` = `КонтурДиадокИнтеграцияУТ11`, `ВызовыПМ` = `КонтурДиадокВызовыПМ`.
- **Как делаем** — одно из действий (подробно — план, шаги 3–4):

| Действие | Что это значит | ТЗ |
|---|---|---|
| **ПМ** | код остаётся в нашем подключаемом модуле; ПМ переезжает из расширения вендора в основную конфигурацию без изменений | ТЗ-3 |
| **Событие** | доработка переписывается на официальное событие ПМ — зацепка не нужна | ТЗ-3 |
| **Тело + зацепка** | наша процедура переезжает в общий модуль основной конфигурации; в расширении — зацепка из одной строки вызова | ТЗ-3 (тело), ТЗ-4 (зацепка) |
| **Зацепка** | метод нашего расширения с аннотацией `&После` / `&Перед` / `&ИзменениеИКонтроль` над методом вендора | ТЗ-4 |
| **Форма кодом** | у заимствованной формы — `&После("ПриСозданииНаСервере")` и вызов нашего модуля, который создаёт элементы | ТЗ-4 |

- **Где наш код** — `т1кДиадокМодули` (общий модуль, сервер), `т1кДиадокФормы` (общий модуль, сервер), `т1кДиадокФормыКлиент` (общий модуль, клиент) — новые, в основной конфигурации; `т1кДиадокСервер` — уже есть в основной конфигурации (ТЗ-0 v3 Ф3); `ПМ` — обработка `ДД_подключаемыйМодуль`; `Расш` — наше расширение `ДиадокДоработки`.
- **Проверка** — эталон X1–X7 (ТЗ-1), пункт smoke S1–S13 (ТЗ-1), проверка шага 0 П1–П17 (ТЗ-0).
