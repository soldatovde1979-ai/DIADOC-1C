> Да, этот файл — моя основная инструкция при работе с данным репозиторием.
> Если ты (агент) начинаешь новую сессию — прочитай этот файл первым.

## 1. Что за проект

Кастомизированный модуль Контур.Диадок для 1С (УТ11), версия вендора 4.61.1.
Расширение конфигурации + правки вендорских модулей с маркером `ШХ`.

## 3. Жёсткие правила

1. **Маркер ШХ** — все кастомизации обозначаются `// ШХ <ID> BEGIN ... // ШХ <ID> END` (формат в ТЗ-2).
   Правки вендорского кода вне ШХ-блоков запрещены без отдельного согласования.
2. **Иерархия решений**: событие хука (`ДД_подключаемыйМодуль`) → расширение (`&Вместо`/`&После`) → патч в реестре.
   Новая кастомизация не «вшивается» в модуль вендора.
3. **Согласование**: перед изменением >1 файла или логики — краткий план и ожидание «ок».
   Для точечных правок одного файла — сразу, но только затронутые строки.
4. **Никакого попутного рефакторинга**: не переименовать, не отформатировать, не удалить «мёртвый» код.
5. **Не выдумывать сущности**: API, пути, имена функций — только из открытых файлов или ТЗ.
   Нужны данные — вывести: `Для генерации ответа необходимы данные:` + список.
6. **Секреты** — только ENV/настройки модуля; в коде и репозитории запрещены.
7. **Отчёт после правок** — строго блоком: «Внесенные изменения / Намеренно не тронуто / Потенциальные риски».

## 4. Как проверять свою работу

- После правок ШХ-блоков: сверка количества блоков до/после.
- После изменения вендорских модулей: патч должен быть отражён в реестре (`tools/patcher/registry`).
- Есть тест-скрипт (ТЗ-7) — прогонять перед сдачей; нет ещё — сверка со слепками `SRC/Baseline-*/manifest.md5`.

## 5. Структура репозитория (ключевое)

```
SRC/ERPDiadok/           — текущая кастомизированная выгрузка модуля
  CommonModules/         — общие модули вендора (не править без патча)
  DataProcessors/КонтурЭДО/Templates/ — модули вендора как макеты (Ядро, ХранениеДанных...)
  DataProcessors/ДД_подключаемыйМодуль/ — НАШ хук (можно править свободно)
  DataProcessors/КонтурЭДО/Forms/     — формы вендора (ШХ-правки → расширение)
SRC/TypeDiadok/          — чистый дистрибутив вендора 4.61.1 (эталон для сравнения)
SRC/Baseline-Исходный/   — слепок «как есть» [планируется]
SRC/Baseline-Целевой/    — слепок «как должно быть» [планируется]
docs/Диадок_РеестрИзменений.md — реестр кастомизаций (23 позиции)
docs/plan.md, docs/tz/   — план и ТЗ
tools/patcher/           — [планируется] скрипт-патчер + реестр патчей
tools/tests/             — [планируется] тест-скрипты
```

## 6. Стиль кода 1С

- Язык — русский (имена переменных/процедур), комментарии в том же стиле, что и вендор.
- Собственные процедуры — префикс `т1к` (исторически) или `шх`; не смешивать с вендорскими именами.
- Отступы — табуляция (как в существующих модулях).
