# Тестовые случаи эталонных XML (X1–X7)

> Версия: 1.0 · 07.10.2026 · ТЗ-2 §2.2. Где выполнять: **тестовая база**, не прод.
> Точка входа вендора — по [R6](../../../docs/research/R6-tochka-vkhoda-etalonov.md) (найдена чтением кода, подтвердить на базе).
> Результат каждого случая — каталог `<Случай>/`: XML документов + `params.json`. Эталон — `expected/<Случай>/`, текущий прогон — `out/reference/actual/<Случай>/`.

## Как читать таблицу

- **Подготовить** — что человек один раз создаёт в тестовой базе. Номера и наименования записать в колонку «Записано» (обработка ищет документы по ним).
- **Ожидание** — что должно получиться словами. Эталон снимается, только если ожидание выполнено глазами.
- **Ловит** — какую порчу нашей доработки покажет отличие.

## Что сохранять (`params.json`)

| Поле | Откуда | Случаи |
|---|---|---|
| `ЗапрашиватьОтветнуюПодпись` | параметры документа в пакете | X2–X5 |
| `Формат`, `ПечатныеФормы` (имена), `ИмяФайла` | `ПараметрыОтправкиВидаДокумента`, документы пакета | X2–X5 |
| `НастройкиДоговора` | результат чтения настроек | X2, X3 |
| `т1кПараметры`, `т1кОтправитель`, `т1кПолучатель` | пакет / результат события ПМ | X2 |
| `Строки[]`: `Наименование`, `ЕдиницаИзмерения`, `Идентификатор` | разбор входящего | X1 |
| `ДанныеХранилища` | чтение обратно | X6 |
| Реквизиты созданного документа (без ссылок и дат) | документ 1С | X7 |

Маскируется (`reference.ps1`): GUID, дата-время, `ВремИнфПр`, `ДатаИнфПр`, `ИдФайл`. Найдётся ещё меняющееся поле — добавить в `Get-Masked`, а не в эталон.

## Обработка формирования эталонов (`ЭталоныXML.epf`) — что должна делать

Пишется на Шаге 2 при живой базе: инициализацию API вендора по коду не проверить.

1. Параметр запуска (`/C`) — каталог результата.
2. Получить объект API вендора (`Обработка.КонтурДиадокВызовыПМ` с инициализированным `Ядро`). Рекомендация R6 — служебная команда внутри нашего ПМ (он получает `ОсновнойМодуль` готовым), видимая только в тестовой базе; тогда `.epf` лишь вызывает её.
3. Для X2–X5: `ЭДО_Модуль_ОбновитьСписокДокументов` с отбором по документу 1С → `ЭДО_ПодготовитьПакетКОтправке(СтрокаСписка)` → сохранить. **Ничего не отправлять.**
4. Для X1: загрузить `input/X1.xml` как входящий → `ЭДО_ПолучитьСтруктурированныйКонтентВходящегоДокумента` → сохранить строки.
5. Для X6: `ЭДО_ПолучитьДанныеДляСохраненияДокументооборота` → сохранить.
6. Записать XML без форматирования (как отдаёт вендор), JSON — с сортировкой ключей (иначе ложные отличия).
7. Завершить сеанс (`ЗавершитьРаботуСистемы(Ложь)`), иначе `update.ps1` будет ждать.

## Проверка, что эталоны не слепые (ТЗ-2, критерий 4)

В тестовой копии убрать параметр `ЕдИзм` в одном вызове `Новый_НоменклатураЭлектронногоДокумента` → `reference.ps1` должен показать отличие в X1. Вернуть. Аналогично для X2: закомментировать передачу `Договор1С` в `Документы_ПараметрыОтправкиВидаДокумента`.
